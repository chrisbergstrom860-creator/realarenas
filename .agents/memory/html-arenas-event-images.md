# Event cover images

- **Storage**: PRIVATE Supabase bucket `event-images` (created idempotently at boot beside `avatars`), paths `events/{eventId}/{ts}.webp`. `events.image_path` (nullable text, user-created via SQL) stores the object path — **server-side only, appears in NO payload**. No public URL exists for any object; no signed URLs (deliberate: SW pathname prefix + rotating-token cache-key problems).
- **Read path**: exactly one — authenticated proxy `GET /api/events/:id/image`, gated by `getVisibleEvent` (the single event access rule; no second path). Nonexistent, denied, and imageless all answer byte-identical 404 `{error:'Event not found'}`. `?v=` is IGNORED server-side — it's purely a cache-bust token. `Cache-Control: private, max-age=31536000, immutable`; replacing changes the timestamp → new URL. SW never caches it (same-origin `/api/*` is network-only, sw.js rule 3).
- **Payload convention**: clients get `image` = numeric version token (timestamp segment via `eventImageVersion()`); `enrichEvent` destructures `image_path` OUT before spreading `...event`. Any new event-shaped payload must do the same — never spread raw `events.*` rows.
- **Why version-token-not-boolean:** stable no-store proxy URLs re-download through the app server every render; the token gives immutable caching with natural busting (same versioned-filename logic as avatars).
- **Upload**: `POST /api/events/:id/image` — creator-only, checked BEFORE multer, zero-leak denial. Reuses avatar pipeline (5 MiB multer, sharp validate + `.rotate()` + 1200×400 cover crop webp q82, `avatarUploadsInFlight` lock key `event:<id>`, pointer-write rollback, replace deletes old object). Entry points: create form (create first, then upload — failed upload never rolls back the create) and an Image action on ALL creator-owned cards (`manageImage` overlay) — the post-creation edit path, since events have no edit UI.
- **Cleanup ordering rule**: DELETE image = pointer null FIRST then best-effort object; event delete + account delete = rows FIRST then best-effort `deleteEventImageObject` (prefix-checked) — object deletion must NEVER block a row delete.
- **Rendering**: no image = nothing (no placeholder/gradient/stock — imageless cards keep original geometry). Desktop events card: 150px `.evx-banner` between tags row and actions row; mobile: 120px `.evx-banner-m` full-card-width top band (`.evx-card` gets flex-wrap in the mobile media block). Thumbs: calendar day panel 44px, member-home 48px, feed RSVP card 56px (replaces the "View →" arrow when present). Club dashboard manager card is DELIBERATELY image-free.
- **Crop step (client-side, server untouched)**: shared `html/arenas-crop.js` (own dual serve route; needs `arenas-overlay.js` loaded first) — dependency-free canvas cropper, fixed 3:1 frame = WYSIWYG preview, SINGLE-axis drag + mirrored slider (cover-fit leaves exactly one free axis; pan-zoom deliberately rejected). Exports 1200×400 PNG (lossless → server WebP q82 stays the only lossy encode) through the existing endpoint; original never uploaded. Large-image safety: decode-time downscale to ≤2400px edge via `createImageBitmap` resize (dims from `<img>` header parse, full-res img drawn only on the bitmap-less fallback) + blank/black-export guard compared against the SOURCE crop region (genuine black photos pass; silent iOS canvas failures fail honestly). **Caller contract**: both entry points use a state machine (`none/pending/ready/fallback`) + monotonic selection token — raw file uploads ONLY on explicit decode-fallback, dismissal clears the input, stale callbacks from superseded selections are dropped, create-submit blocks while `pending`. Never wire a new consumer without the token/state pattern.
- **Write authorization**: ONE shared `canManageEvent(event, userId)` = creator OR admin/coach of `event.club_id`; PATCH, DELETE and both image routes call it — never re-inline the rule (`requireEventManager` is a DIFFERENT club-only rule for coach tools, no creator arm). Response shape stays per-route: PATCH/DELETE give visible-but-unauthorized callers a distinct message; image routes stay byte-identical not-found pre-multer. Payload injects `canManage` (UI affordance only) → Image action shows for club managers on non-owned cards; club dashboard stays image-action-free by decision. Timing delta (extra memberships query for real club events vs ghost) accepted — same delta exists app-wide via getVisibleEvent; private events short-circuit (club_id null).
- **Guards**: `scripts/verify-crop-ui.js` (drives the real slider+button on sentinel-band sources; extremes must differ — fails if offset ignored; black-source no-false-positive; decode fallback). Also: `scripts/verify-event-images.js` (byte-diff no-oracle sweep incl. unauth, payload/export scans for `image_path|storage/v1`, replace/remove/event-delete/account-delete orphan checks via bucket prefix listing, self-cleaning with error-checked user deletion — silent `deleteUser` failures leave baseline residue). Geometry seeds real objects on all seeded events (broken `<img>` has zero height → banner would be silently unmeasured) and sweeps the prefix in teardown.
