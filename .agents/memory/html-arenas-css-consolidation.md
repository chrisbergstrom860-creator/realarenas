Batch 1 (Jul 2026) moved 10 base-chrome rules into `html/arenas.css` ("Base chrome (consolidated, Batch 1)" section, placed BEFORE the mobile @media so mobile overrides still win). Three traps were hit and must govern every future batch:

1. **Membership by `<link>` tag, not grep.** `grep -l arenas.css` matched a *comment* in arenas-club-invite.html saying it does NOT link the file. Only 11 pages truly link arenas.css: athletes, billing, calendar, challenges, club-dashboard, club-member, events, feed, leaderboards, log, my-profile. club-invite is self-contained. Always use `grep -l '<link[^>]*arenas.css'`.
   **Why:** editing club-invite as "linked" stripped its only copies → 48% pixel diff.

2. **Partial coverage = scope expansion.** A rule identical on the pages that carry it still can't move if some linked pages DON'T carry it and the selector can match their DOM (element/universal selectors always match). `button,select,input,textarea{font-family}` was on only 6/11 pages — moving it restyled every form control on the other 5.
   **How to apply:** for each candidate, list carriers; non-carriers need proof the selector matches nothing there (class unused in markup AND JS), or the rule stays page-local.

3. **Same-specificity demotion vs sibling rules, not just duplicates.** `.btn-yellow/.btn-primary/.btn-ghost` conflict with each page's LOCAL `.btn` (font-weight:500, sometimes background) at equal specificity; moving the variants earlier (arenas.css) lets `.btn` win. The hazard rule: check every earlier page rule that shares *properties* with the candidate on the same elements, not just same-selector copies. Safe movers: higher-specificity state rules (`.modal-overlay.open`, `.toast.show`), zero-specificity reset, and standalone classes sharing no props (`.btn-full`, `.card`, `.footer*`, `.notif-btn`).

**Verification recipe that works:** throwaway shot script (coach test user, 12 surfaces × 1280/380) against a clean-HEAD baseline taken in the SAME session; `cmp` + `compare -metric AE`; ≤~120px on live-data pages is dynamic noise (prove by re-shooting HEAD). Re-shoot the HEAD baseline fresh if runs are separated — data drift (memberships, time-ago) produces multi-thousand-px false diffs.

SW note: arenas.css is served network-first (sw.js Rule 5, same-origin asset → networkFirst); no cache-bust needed beyond deploy.

**Batch 2 (Jul 2026) — button system.** Canonical `.btn`/`.btn:hover` + ghost/primary/yellow variants now in arenas.css, ordered .btn → .btn:hover → variants → variant hovers (variants must stay after base or they demote). Canonical .btn has NO background/color (bare `.btn` buttons on club-dashboard/my-profile inherit gray-800) but DOES keep font-family (challenges/leaderboards lack the element font rule). athletes/billing/events keep FULL local .btn cascades + local variant copies — their padding/background divergences are real, and any page-local `.btn` demotes arenas.css variants, so a page either deletes its whole button cascade or keeps all of it. challenges/leaderboards normalized: body 15→14px, .btn/.toast → canonical 13px. Accepted side effect: pages without a prior .btn:hover now get gray-100 hover on variant-less buttons.

**Batch 3 (Jul 2026) — modal cluster.** Canonical `.modal-overlay/.modal/.modal-header/.modal-body/.modal-close/.modal-footer` in arenas.css. Canonical .modal carries NO max-width and NO animation — per-modal sizing and entrance animations are deliberate per-page overrides, each keyframe LOCAL to its page (never reference a page keyframe from arenas.css). Carrier overrides: athletes (560px, fade-up, zero-padding borderless block header for full-bleed hero), calendar (day-panel: 480px/14px radius/82vh/lighter shadow, sticky header, `.modal-body{display:block}` REQUIRED or canonical flex+gap relayouts), club-dashboard 580px/modal-in, club-member 560px/modal-in, my-profile 500px/scale-in (its radius-xl/shadow-lg/26px family was drift, normalized).

Key findings:
1. **Much static modal markup is DEAD.** 7 of 16 statically-declared modals have no opener anywhere (dashboard modal-event/-event-rsvp/-challenge; all 3 on club-member; my-profile modal-comment). challenges + feed had full `.modal*` CSS clusters with ZERO modal markup — deleted outright, pixel-proven no-op. Always grep for openers (openModal/classList.add('open')) before treating modal CSS as live.
2. **Class-named runtime overlays inherit canonical CSS.** events' runtime `#evx-modal` overlay uses class="modal-overlay" with inline cssText — inline wins per-property, but properties NOT set inline (backdrop-filter) now arrive from canonical. Accepted side effect: events create-modal backdrop gained blur(3px), consistent with the rest.
3. **Geometry guard now audits modals permanently.** verify-mobile-geometry.js has 13 modal-open step states (561 assertions total); engine lesson: `inFixed` exclusion walk must stop at the audit ROOT, not document.body, or fixed modal overlays used as roots are structurally blind (root='body' behavior unchanged). Sticky elements INSIDE a modal root are still excluded — acceptable.
4. **Pre-existing modal geometry defects (NOT fixed in Batch 3, open):** 9 failures — create-challenge overlay form labels overlap footer buttons at 360-414px; invite-manager follower rows overlap Send-invites button; events create-event invitee labels overlap Create-event button. Real overlaps (footers are static, not sticky). Fix as separate task.

**Batch 3 follow-up (Jul 2026) — modal defect triage + dead-modal deletion.** The 9 "modal geometry defects" were ENGINE false positives, not CSS bugs: the text-overlap rule used unclipped client rects, so rows scrolled out of an inner overflow-y:auto container (70vh modal body, max-height invite lists) "overlapped" the button below on paper only. Engine now intersects each text rect with every overflow-clipping ancestor before overlap testing (fully clipped leaves drop out); genuine visible overlaps are unaffected. Lesson: when a guard flags overlap involving content inside a scroll container, MEASURE clipped visibility before assuming a layout bug. The 7 dead prototype modals + their orphaned CSS/JS were deleted (club-member now has ZERO modal machinery — no openModal/closeModals/.modal CSS; dashboard keeps club-logo + runtime RSVP overlay; my-profile keeps avatar/delete/goal). Pre-existing def-only orphans (.pill-new/-run/-cyc/-swm/-clm on dashboard) left in place, noted not deleted.

**Final item (Jul 2026) — :root union-merge DONE.** Shared arenas.css :root now carries the full palette union (added green/blue/orange/purple-light, teal, teal-light, pink/pink-light/pink-dark, radius-xl, shadow-lg); the 7 linked pages' :root copies are deleted (billing/calendar/leaderboards/log never had one). --shadow-lg conflict resolved by majority to `0 10px 40px rgba(0,0,0,0.12)` — challenges' overlays intentionally softened from `.16/12px/32px`. PERMANENT guard `scripts/verify-css-vars.js` (479 assertions): every var(--x) a page+its scripts consume must resolve in shared :root (linked) or page-locally (self-contained); comments stripped pre-parse; conservative scope model documented in-file. It already caught 2 silent pre-existing bugs (landing-login var(--green), club-dashboard var(--shadow-lg) ×3) — unresolved var() is SILENT in the browser, so run this guard whenever touching :root or adding var() refs.
